# Deploy Kammel for free

Everything below costs **0 €**, needs **no credit card**, and keeps working even if nobody opens the app for a month.

| Part | Service (free plan) | What it hosts |
| --- | --- | --- |
| Web app (PWA) | **Cloudflare Pages** | `web/` — static files + a tiny proxy function for `/api` |
| API | **Render** (Free web service) | `backend/` — Express |
| Database | **TiDB Cloud Starter** | MySQL-compatible database (5 GiB free) |
| Keep-alive | **cron-job.org** | pings the API every 10 min so it never sleeps |

```
phone / PC ──► https://kammel.pages.dev ──(static files)
                     │  /api/*  (Pages Function adds a secret header)
                     ▼
              https://kammel-api.onrender.com ──► TiDB Cloud (TLS)
```

Why this layout:
- The browser only ever talks to `kammel.pages.dev`, so the login cookie stays *same-site* (`SameSite=Strict`, `HttpOnly`, `Secure`) — no CORS, no third-party cookies (iPhones block those).
- The API only accepts requests that carry the proxy's secret header: the raw Render URL is closed to the public.
- Cloudflare Pages never sleeps and allows commercial use (Vercel's free plan does not).
- Render's free web service sleeps after 15 min without traffic; the keep-alive ping prevents that, and one always-on service uses ~744 h of the 750 free hours per month.

## 0. Before you start

1. Push the project to GitHub (private repo is fine): `git add . && git commit -m "Kammel" && git push`.
   Check that **`backend/.env` is NOT committed** (it is listed in `.gitignore`).
2. Generate two secrets on your PC and keep them in a password manager:
   ```
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # → PROXY_SECRET
   ```
   (`JWT_SECRET` is generated by Render automatically.)

## 1. Database — TiDB Cloud Starter

1. Sign up at https://tidbcloud.com → **Create Cluster** → **Starter** (free) → region close to Render's (e.g. *Frankfurt / eu-central-1*).
2. Open the cluster → **Connect** → *Connect with: General*, *Operating system: your OS* → **Generate password**.
3. Copy the values and build the URL (the default database can be anything; we use `kammel`):
   ```
   DATABASE_URL=mysql://<USER>:<PASSWORD>@<HOST>:4000/kammel
   ```
   (`<USER>` looks like `xxxxxxxx.root`. If the password contains `@ : / ?`, URL-encode it.)
4. Create the tables and the first data **from your PC** (Render's free plan has no shell). In `backend/`:
   ```
   # PowerShell
   $env:DATABASE_URL="mysql://...:4000/kammel"; $env:DB_SSL="true"; npm run db:setup -- --yes
   # Git Bash
   DATABASE_URL="mysql://...:4000/kammel" DB_SSL=true npm run db:setup -- --yes
   ```
   This creates every table and the demo data (gym « Kammel Gym Lac 2 », staff, members…).
   > ⚠️ Demo accounts all use the password `Kammel2026!` which is written in this repo.
   > For a real gym: right after the first login, change the admin and gérant passwords (Compte → Mot de passe),
   > and deactivate demo members you don't need (Admin → Utilisateurs). `--yes` is required because
   > `db:setup` **erases** all tables of that database — never run it again on a database with real data.

## 2. API — Render

1. Sign up at https://render.com with your GitHub account.
2. **New → Blueprint** → pick your repo. Render reads `render.yaml` and proposes the service **kammel-api** (free plan).
3. Fill the variables Render asks for:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | the TiDB URL from step 1 |
   | `PROXY_SECRET` | the secret you generated |
   | `GEMINI_API_KEY` | optional — free key from https://aistudio.google.com/apikey (AI coach, meal photo scan) |
   | `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` | optional — staff "forgot password" e-mails (e.g. Gmail app password, or Brevo free SMTP). Leave empty to skip. |

   Already set by `render.yaml`: `NODE_ENV=production`, `NODE_VERSION=22`, `SERVE_WEB=false`, `TRUST_PROXY=1`, `DB_SSL=true`, `JWT_SECRET` (random, generated by Render).
4. **Apply**. When the deploy is green, open `https://kammel-api.onrender.com/api/health` → `{"ok":true,"db":true,…}`.
   (Every other `/api` URL answers `403` here: that's expected, the API only accepts the proxy.)
   If Render gave you another name (e.g. `kammel-api-x1y2.onrender.com`), use that address below.

## 3. Web app — Cloudflare Pages

1. Sign up at https://dash.cloudflare.com → **Workers & Pages → Create → Pages → Connect to Git** → pick your repo.
2. Build settings:

   | Setting | Value |
   | --- | --- |
   | Framework preset | *Vite* (or None) |
   | Root directory | `web` |
   | Build command | `npm ci && npm run build` |
   | Build output directory | `dist` |

3. **Environment variables** (Production, *encrypt* `PROXY_SECRET`):

   | Variable | Value |
   | --- | --- |
   | `API_ORIGIN` | `https://kammel-api.onrender.com` (your Render URL, no trailing slash) |
   | `PROXY_SECRET` | the **same** secret as on Render |
   | `NODE_VERSION` | `22` |

4. **Save and Deploy**. Your app is at `https://<project>.pages.dev`. Open it on your phone → browser menu → **Add to Home Screen** to install it as an app.
   (Optional: Custom domains → add your own domain; nothing else to change.)

## 4. Keep-alive — cron-job.org

1. Sign up at https://cron-job.org (free) → **Create cronjob**.
2. URL: `https://<project>.pages.dev/api/health` — every **10 minutes** — save.
   This keeps Render awake (no 1-minute cold start), keeps the background jobs running (expiry reminders, scheduled messages, calm-gym alerts) and touches the database so it stays active.
   You also get an e-mail if the app ever goes down.

## 5. Updating the app

Push to GitHub → Render and Cloudflare rebuild automatically. Database changes: if a new version adds tables, the server creates them on start; if it changes existing ones, the server stops with a message asking for `db:setup` — on a database with real data, export it first (TiDB console → Export).

## Environment variables — summary

**Render (API)**: `DATABASE_URL`, `DB_SSL=true`, `JWT_SECRET` (auto), `PROXY_SECRET`, `NODE_ENV=production`, `NODE_VERSION=22`, `TRUST_PROXY=1`, `SERVE_WEB=false`, optional `GEMINI_API_KEY`, `GEMINI_MODEL`, `SMTP_*`, `MAIL_FROM`.
**Cloudflare Pages (web)**: `API_ORIGIN`, `PROXY_SECRET`, `NODE_VERSION=22`.
**Your PC (`backend/.env`, local only, never committed)**: `DB_*` or `DATABASE_URL`, `JWT_SECRET`, optional `GEMINI_API_KEY`, `SMTP_*`.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| App shows « Serveur injoignable » / `PROXY_NOT_CONFIGURED` | `API_ORIGIN` / `PROXY_SECRET` missing on Cloudflare → set them, then *Retry deployment*. |
| Every API call returns 403 | `PROXY_SECRET` differs between Cloudflare and Render. |
| Render deploy fails: `JWT_SECRET manquant ou trop faible` | Set a random `JWT_SECRET` of 32+ characters. |
| `/api/health` → `db:false` | Wrong `DATABASE_URL`, or `DB_SSL` not `true`. |
| Server log: « La base date de l'ancienne version » | Run step 1.4 against the database. |
| First request after a long pause takes ~1 min | The keep-alive cron isn't running (step 4). |
