## Rules
- Put each feature's code in `src/features/<feature>/` (pages, local components, `strings.js`, optional `<feature>.css` imported by the page). Never edit another feature's folder.
- **Every user-visible string goes through `t()`** with keys prefixed by your feature, in `strings.js` with **fr, ar AND en** (Tunisian-flavoured Arabic like the design: e.g. «الماكينة محجوزة؟ كمّل», «القاعة توّا», «زيد ماكلة»; short, second person, energetic, never preachy). Kashida (ـــ) only in short Arabic labels/eyebrows/tab names, never in body text, buttons or numbers.
- Numbers: wrap displayed numbers with `<Num>` or a `<span className="num">` (so «1 240» isn't reversed in RTL). `.num` is inline-block: never put it on a block/flex-item element (it would left-align in RTL) — wrap the number inside instead. Use `fmt.*` for formatting; big numbers use `.big-num` (put the `.num` span inside).
- Git Bash rewrites command-line arguments starting with `/` into Windows paths; `shot-app.js` undoes this for route paths, but for other tools prefix commands with `MSYS_NO_PATHCONV=1` when needed.
- Button variants: primary | secondary | ghost | text | warn | warn-soft (« Occupée ») | danger (soft, « En panne ») | danger-solid | hydro.
- RTL: use logical CSS (`margin-inline-start`, `inset-inline-end`, `padding-inline`, `text-align: start`), never `left/right` for layout. Directional icons flip automatically.
- Colours only via CSS variables. No new hex colours in JSX/CSS (except inside `tokens.css`). Inline `style` only for dynamic values (widths, heights).
- Each data screen: skeleton while loading (`PageSkeleton`/`Skeleton`), `Empty` state, `ErrorState` with retry, and offline behaviour where relevant (`OfflineBanner`). Forms: disabled primary button until valid, inline field errors (`Field error=`), server errors via `FormError` or toast with `i18n.error(err)`.
- Bottom sheets (`<Sheet>`) instead of centred modals on phones; on desktop staff pages use `variant="drawer"` for detail panels and `variant="center"` for forms.
- Tap targets ≥ 48 px, primary actions in `.sticky-bar` on mobile screens.
- **Security**: never use `dangerouslySetInnerHTML`; never build URLs from user/API strings for navigation without `safeInternalPath`; never put tokens/passwords/health data in localStorage (UI prefs only); show temporary passwords returned by the API once, with a copy button, and never persist them; render user-provided text as text only; photo uploads go through `shrinkPhoto` (re-encodes, strips EXIF).
- No new npm dependencies. No TODO/placeholder/stub screens, no fake hard-coded data in screens (all data from the API; empty states when there is none). No `console.log` left.
